# Keto: Complete Plugin Reference

Every plugin with a two-line summary of **what it does** and **how it does it**, plus the Volatility 3 plugin it is the GPU counterpart of. Generated from the plugins' own metadata by `tools/gen_docs.py` (Keto 1.0.0, 110 plugins).

- **Usage:** `keto -f <image> <plugin> [options]` for memory images, `keto --live <plugin>` on a running system, `keto -f <snapshot.keto> <plugin>` to replay a captured live snapshot offline.
- **Needs:** `image` = a GPU memory image (`.keto` container, raw VRAM dump, LiME); `live` = the running system or a recorded snapshot; `file` = only the files named in its options, or for the `host.*` / `wsl.*` plugins a host RAM image (`-f` or `--host-image`, plus `--btf`/`--kallsyms` for images from other tools) or the running kernel (`--kcore`, root).
- Output formats: `-r quick|pretty|csv|json|jsonl`; files go to `-o <dir>`.

## Framework / vendor-independent plugins (10)

| Plugin | Needs | Volatility analogue | What it does | How it does it |
|---|---|---|---|---|
| `banners` | image | banners | Finds NVIDIA driver, CUDA, VBIOS and GPU-product banners (and host kernel banners) to identify the exact driver/hardware the image came from. | Regex-scans the primary layer (and --host-image) for known banner formats; de-duplicates by text. |
| `configwriter` | image | configwriter | Saves what the automagic detected (profile and why, layers, VRAM size, address spaces) so later runs and reports can reuse it. | Runs profile detection and address-space discovery, then writes config.json to the output directory. |
| `frameworkinfo` | file | frameworkinfo | Lists the installed framework components: plugins per category, renderers, profiles, layers. | Enumerates the plugin registry, renderer table and profile registry. |
| `hexdump` | image | volshell db/dq | Hex-dumps bytes from any layer (physical VRAM, host memory, or a GPU virtual address space). | Reads through the chosen layer (translating GPU VAs via the page tables) and formats 16 bytes per line. |
| `layerwriter` | image | layerwriter | Exports a layer to a flat file: the primary/physical layer (gaps zero-filled) or any GPU address space (readable runs back to back, plus a .map file). | Reads the selected layer's readable runs in 4 MiB blocks; physical layers are written at their own offsets, virtual layers sequentially with an offset map. |
| `profileinfo` | file | isfinfo | Lists the available GPU architecture profiles (the symbol tables of this framework), what hardware each covers, and validates them. | Loads every profile JSON from the built-in symbols directory and --profile-dir, validates the schema, and prints architecture, chipsets, MMU format, structure layout, QMD version and provenance. |
| `regexscan` | image | regexscan | Searches a layer (default: the primary physical layer) for a regular expression. | Runs a bytes regex chunk by chunk with overlap so matches across chunk boundaries are kept. |
| `timeliner` | image/live | timeliner | Builds one time-sorted timeline from every plugin that produces timestamps (GPU processes, accounting history, Xid errors, compute-cache files, acquisition metadata). | Runs every plugin implementing TimeLinerInterface whose data source is available, collects (description, type, time) events and sorts them; --create-bodyfile writes a mactime body file. |
| `verify` | image | (chain of custody; no direct Volatility analogue) | Verifies the integrity of a .keto evidence container (SHA-256 of every segment against its metadata). | Re-reads each segment from the container file and compares its SHA-256 with the hash recorded at acquisition. |
| `yarascan` | image | yarascan | Scans a layer (default: primary physical layer) with YARA rules. | Compiles rules with yara-python and scans the layer in overlapping 16 MiB chunks. |

- `banners` options: `--limit`
- `hexdump` options: `--address`, `--length`, `--layer`
- `layerwriter` options: `--layer`, `--list`
- `profileinfo` options: `--provenance`
- `regexscan` options: `--pattern`, `--layer`, `--max-length`
- `timeliner` options: `--create-bodyfile`, `--plugin-filter`
- `yarascan` options: `--yara-rules`, `--yara-file`, `--layer`, `--builtin`

## Channels, TSGs and scheduling (the GPU's processes) (10)

| Plugin | Needs | Volatility analogue | What it does | How it does it |
|---|---|---|---|---|
| `nvidia.chanscan` | image | windows.psscan / linux.psscan | Finds GPU channel instance blocks (the per-channel hardware context), including channels that are no longer scheduled. | Checks the RAMFC signature word (NV_PPBDMA_SIGNATURE_HW_VALID = 0xFACE at +0x10) of every 4 KiB-aligned page, then validates the page directory base (+0x200), GPFIFO base/size (+0x48) and USERD pointer; USERD is read for the live GP_GET/GP_PUT. |
| `nvidia.chantree` | image | windows.pstree / linux.pstree | Shows channels as a tree: GPU address space (one per process/context) -> channels -> subcontexts (VEIDs), so engines working for the same process are grouped. | Groups validated instance blocks by the page directory they (or their Volta+ subcontext PDB entries at RAMIN+0x2A0) point at; TSG membership comes from the runlist scan. |
| `nvidia.contexts` | image | windows.kpcrs / thread context (saved register state) | Shows, per channel, where the engine's saved execution state lives: the context-switch image (the GPU's equivalent of saved CPU registers), its addressing mode, the subcontext (VEID), PASID/ATS binding and the engine method buffer, with a preview of the saved state. | Decodes NV_RAMIN_ENGINE_WFI (TARGET 1:0, MODE 2 physical/virtual, CS 3 WFI/FG, PTR 31:12 + HI), NV_RAMIN_ENGINE_WFI_VEID, NV_RAMIN_PASID / ENABLE_ATS and NV_RAMIN_ENG_METHOD_BUFFER_ADDR; virtual pointers are translated through the channel's page tables and the first bytes are read. |
| `nvidia.gpfifo` | image | windows.threads / linux.pslist (threads) | Lists every GPFIFO (command submission ring) entry of every channel: pushbuffer segment address, length, whether the GPU already consumed it, and what it contains. | Reads the ring at RAMFC GP_BASE (size 1 << LIMIT2) through the channel's GPU address space; decodes NVC56F_GP_ENTRY0/1 (GET, GET_HI, LENGTH, LEVEL, SYNC) and classifies each entry against USERD GP_GET/GP_PUT. |
| `nvidia.orphanchans` | image | windows.orphan_kernel_threads | Finds channels whose own structures do not resolve: GPFIFO, USERD or page directory outside VRAM or unmapped in the channel's address space (stale, corrupted or forged contexts). | For each signature-valid instance block, translates GP_BASE through its address space, checks USERD lies inside VRAM, and checks the page directory walk produced at least one mapping. |
| `nvidia.pending` | image | windows.suspended_threads | Lists channels with submitted-but-unexecuted work (GP_GET != GP_PUT) at acquisition time, and the commands that were about to run. | Compares USERD GP_GET/GP_PUT (falling back to the RAMFC copies) and reports the ring entries in [GP_GET, GP_PUT) with their decoded events. |
| `nvidia.privileges` | image | windows.privileges / linux.capabilities | Reports privileged channels (kernel/RM channels) and privileged page mappings, flagging privileged pages inside address spaces used by unprivileged channels. | Reads the RAMFC HCE_CTRL privilege bit (bit 5) of each instance block and the PTE PRIVILEGE bit (VER2 bit 5; VER3 PCF bit 1) of every mapping in each address space. |
| `nvidia.runlist` | image | windows.pslist (list walking) / linux.pidhashtable | Lists the scheduler's runlists: every timeslice group (TSG) and the channels it schedules, with each channel's instance block and USERD. | Volta+: signature-scans 16-byte NV_RAMRL_ENTRY TSG headers (TYPE=1, sane timeslice, length 1..128, word3=0) and validates the channel entries (INST_PTR, USERD_PTR, CHID). Maxwell/Pascal: anchors on each instance block's address >> 12 in word1 of 8-byte entries and walks back to the TSG header. | `nvidia.timeslices` | image | windows.timers / mac.timers | Reports each TSG's scheduling timeslice and flags groups configured far above the driver default (GPU monopolisation by cryptojackers or denial-of-service workloads). | Decodes NV_RAMRL_ENTRY_TSG_TIMESLICE_SCALE (19:16) and TIMEOUT (31:24); the effective slice is TIMEOUT << SCALE ticks. The driver default is TIMEOUT=128, SCALE=3. |
| `nvidia.tsglist` | image | windows.joblinks | Lists timeslice groups (TSGs) and their member channels with per-channel ring state. | Reads TSG headers and member channel entries from the runlist scan and joins each member with its decoded instance block (GPFIFO, GP_GET/GP_PUT, address space). |
