# Keto: Complete Plugin Reference

Every plugin with a two-line summary of **what it does** and **how it does it**, plus the Volatility 3 plugin it is the GPU counterpart of. Generated from the plugins' own metadata by `tools/gen_docs.py` (Keto 1.0.0, 116 plugins).

- **Usage:** `keto -f <image> <plugin> [options]` for memory images, `keto --live <plugin>` on a running system, `keto -f <snapshot.keto> <plugin>` to replay a captured live snapshot offline.
- **Needs:** `image` = a GPU memory image (`.keto` container, raw VRAM dump, LiME); `live` = the running system or a recorded snapshot; `file` = only the files named in its options, or for the `host.*` / `wsl.*` plugins a host RAM image (`-f` or `--host-image`, plus `--btf`/`--kallsyms` for images from other tools) or the running kernel (`--kcore`, root).
- Output formats: `-r quick|pretty|csv|json|jsonl`; files go to `-o <dir>`.

## Framework / vendor-independent plugins (10)

| Plugin | Needs | Volatility analogue | What it does | How it does it |
|---|---|---|---|---|
| `banners` | image | banners | Finds NVIDIA driver, CUDA, VBIOS and GPU-product banners (and host kernel banners) to identify the exact driver/hardware the image came from. | Regex-scans the primary layer (and --host-image) for known banner formats; de-duplicates by text. |
| `configwriter` | image | configwriter | Saves what the automagic detected (profile and why, layers, VRAM size, address spaces) so later runs and reports can reuse it. | Runs profile detection and address-space discovery, then writes config.json to the output directory. |
| `frameworkinfo` | file | frameworkinfo | Lists the installed framework components: plugins per category, renderers, profiles, layers. | Enumerates the plugin registry, renderer table and profile registry. |
| `hexdump` | image | volshell db/dq | Hex-dumps bytes from any layer (physical VRAM, host memory, or a GPU virtual address space). | Reads through the chosen layer (translating GPU VAs via the page tables) and formats 16 bytes per line; bytes that are not backed by the layer (unmapped VAs, gaps, beyond the image) are reported in the Unbacked column and shown as zeros. |
| `layerwriter` | image | layerwriter | Exports a layer to a flat file: the primary/physical layer (gaps read back as zeros; the file is sparse, so gaps take no disk space) or any GPU address space (readable runs back to back, plus a .map file). | Reads the selected layer's readable runs in 4 MiB blocks; physical layers are written at their own offsets into a sparse file, virtual layers sequentially with an offset map. |
| `profileinfo` | file | isfinfo | Lists the available GPU architecture profiles (the symbol tables of this framework), what hardware each covers, and validates them. | Loads every profile JSON from the built-in symbols directory and --profile-dir, validates the schema, and prints architecture, chipsets, MMU format, structure layout, QMD version and provenance. |
| `regexscan` | image | regexscan | Searches a layer (default: the primary physical layer; any GPU address space as as_<pdb>) for a regular expression. | Runs a bytes regex chunk by chunk with overlap so matches across chunk boundaries are kept. |
| `timeliner` | image/live | timeliner | Builds one time-sorted timeline from every plugin that produces timestamps (GPU processes, accounting history, Xid errors, compute-cache files, acquisition metadata). | Runs every plugin implementing TimeLinerInterface whose data source is available, collects (description, type, time) events and sorts them; --create-bodyfile writes a mactime body file. Sources that read the analyst machine's own files by default (JIT and shader caches) are only included when the evidence is this live system (--live). |
| `verify` | file | (chain of custody; no direct Volatility analogue) | Verifies the integrity of a .keto evidence container (VRAM, host RAM, process, CUDA residual or live-snapshot containers): every segment's SHA-256, the segment table, the metadata and the evidence fingerprint recorded at acquisition. | Re-reads each segment and compares its SHA-256 and table entry with the metadata; recomputes the SHA-256 over all data against data_sha256; checks the header digest that covers the header fields, metadata and segment table (version 2 containers); --expected-fingerprint compares the evidence fingerprint with the value recorded outside the container at acquisition. |
| `yarascan` | image | yarascan | Scans a layer (default: primary physical layer) with YARA rules. | Compiles rules with yara-python and scans the layer in overlapping 16 MiB chunks. |

- `banners` options: `--limit`
- `hexdump` options: `--address`, `--length`, `--layer`
- `layerwriter` options: `--layer`, `--list`
- `profileinfo` options: `--provenance`
- `regexscan` options: `--pattern`, `--layer`, `--max-length`
- `timeliner` options: `--create-bodyfile`, `--plugin-filter`
- `verify` options: `--expected-fingerprint`
- `yarascan` options: `--yara-rules`, `--yara-file`, `--layer`, `--builtin`

## Channels, TSGs and scheduling (the GPU's processes) (10)

| Plugin | Needs | Volatility analogue | What it does | How it does it |

| `nvidia.orphanchans` | image | windows.orphan_kernel_threads | Finds channels whose own structures do not resolve: GPFIFO, USERD or page directory outside VRAM or unmapped in the channel's address space (stale, corrupted or forged contexts). | For each signature-valid instance block, translates GP_BASE through its address space, checks USERD lies inside VRAM, and checks the page directory walk produced at least one mapping. |
| `nvidia.pending` | image | windows.suspended_threads | Lists channels with submitted-but-unexecuted work (GP_GET != GP_PUT) at acquisition time, and the commands that were about to run. | Compares USERD GP_GET/GP_PUT (falling back to the RAMFC copies) and reports the ring entries in [GP_GET, GP_PUT) with their decoded events. |
